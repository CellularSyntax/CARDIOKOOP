# CARDIOKOOP — reproducibility guide (release v1.2.0)

This document gives every number, table and figure of the article
*"Real-Time Hemodynamic Prediction via Control-Aware Koopman Operator Models"* (Haberbusch et al., **Array**, 2026)
a committed file of origin and the script that regenerates it, and documents the metric conventions, the frozen
model artefacts, the statistics, the numerical-reproducibility properties across platforms and the container-based
verification that runs in continuous integration.

**Evaluation split for every reported number:** the seed-42 **test1** split
(`data/csv_data_500_12sigs_test1_{x,u}.csv`; 50 trajectories × 1500 steps × 12 signals, 1499-step autoregressive
horizon). **Frozen Koopman checkpoint:** `results/koopman/csv_data_500_12sigs_2025_06_18_18_50_13_876051_model.ckpt`
(17,239,600 parameters). **Statistical unit:** the test trajectory (n = 50); 95 % CI = 1.96·SD/√50 across trajectories.

Folder conventions used below:

| Folder | Content |
|---|---|
| `scripts/experiments/` | baseline, ablation and robustness experiments (`task1_*.py` … `task9_*.py`, `task_a_*.py` … `task_f_*.py`, `build_tables_figures.py`, `run_all.py`, figure builders, shared `_common.py`) |
| `scripts/tables/` | table export and verification (`export_manuscript_tables.py`, `compare_results.py`) |
| `results/experiments/` | experiment outputs (CSV/TeX/JSON) written by `scripts/experiments/` |
| `results/tables/` | manuscript Tables 3–5, statistics, R² conventions, test1 Koopman pickle, run metadata — written by `scripts/tables/export_manuscript_tables.py` |
| `results/*.json`, `results/{koopman,lstm,gru,bilstm,dlinear,nlinear,mlp}/` | outputs of `task1_*.py` … `task9_*.py`, model checkpoints and post-processing pickles |

Everything in `results/tables/` is produced by **one** command (about one minute on CPU):

```bash
python scripts/tables/export_manuscript_tables.py
```

The experiment folder is regenerated with `python scripts/experiments/run_all.py` (steps, in order: `task_a_dlinear_nlinear.py`,
`task_b_gamma_sweep.py`, `task_c_activation.py`, `task_d_realistic_streaming_noise.py`, `task_e_mode_ablation_export.py`,
`task_f_clean_reanchoring.py`, `build_tables_figures.py`, `regenerate_panels_a_gj.py`, `figure_mode_analysis.py`,
`figure_latent_hparam.py`; `run_all.py a build panels` runs a subset). The experiments `task1_*.py` … `task9_*.py`
are standalone scripts that write to `results/*.json`.

Headline experiment results (test1, frozen checkpoint, no retraining of the main model):

* **Direct linear baselines** (`task_a_dlinear_nlinear.py`): DLinear 3.03 %RMSE (± 0.61), R² = 0.983, 429,120 parameters;
  NLinear 3.63 %RMSE (± 0.63), R² = 0.982, 214,560 parameters. Direct multi-step forecasters avoid the error accumulation of the
  1499-step autoregressive rollout; the Koopman model remains the most accurate autoregressive / dynamical model (3–5× lower error
  than every RNN baseline) and is far more noise-robust (Table 5: Koopman 17.5 → 41.7 % at 5 dB; DLinear 3.0 → 334 %,
  NLinear 3.6 → 1029 %, AR(20) 34 → 2967 %).
* **Control-gain γ sweep** (`task_b_gamma_sweep.py`, Fig. S7): γ = 0 (control ablation) 51.37 %RMSE / R² −3.93; γ = 0.05
  47.92 / −1.72; γ = 0.10 (trained) 17.54 / 0.691; γ = 0.20 49.27 / −0.19; γ ≥ 0.5 diverges.
* **Control-net output activation** (`task_c_activation.py`, Table S4): tanh (deployed) 17.5 / 0.691 and identity 15.9 / 0.618
  give stable rollouts; ReLU collapses to the no-control error (51.4 / −4.17) and sigmoid diverges — a zero-centred output
  activation is required.
* **Realistic and streaming noise** (`task_d_realistic_streaming_noise.py`, Fig. S8, Table S6): AWGN + baseline wander on the
  initial condition gives 18.2 / 23.6 / 34.6 %RMSE at 30 / 20 / 10 dB (diverges at 5 dB); streaming re-anchoring every
  K = 100 steps gives 5.8 / 11.9 / 25.2 / 35.9 %RMSE at 30 / 20 / 10 / 5 dB.
* **Mode ablation** (`task_e_mode_ablation_export.py`): baseline 17.54 %RMSE; ablating the dominant cardiac mode CP-3
  (|f| ≈ 1.77 Hz) adds +16.4 pp (+93 % relative); CP-2 +3.6 pp, CP-1 +2.4 pp, CP-0 +1.9 pp.

## 2. R² conventions (definitions in `results/tables/r2_conventions.json`)

Three R² definitions occur in the manuscript; the manuscript states explicitly which is used where.

| Convention | Definition | Used in |
|---|---|---|
| **Pooled per-trajectory R²** | 1 − SS_res/SS_tot over all 12 signals × 1500 steps of one trajectory concatenated (`_common.r2_flat`); reported as mean ± 95 % CI over the 50 trajectories | Table 3, Table 5, Fig. 5g, Fig. S10 caption, Table S4 |
| **Per-signal R²** | `sklearn.metrics.r2_score` of one signal of one trajectory; mean ± 95 % CI over trajectories | Table 4, Fig. 5h |
| **Signal-averaged per-trajectory R²** | mean of the 12 per-signal R² of one trajectory (`r2_per_trajectory` key of the pickles) | "trajectories with R² < 0" statements of the per-signal analysis |

Test1 results (`r2_conventions.json`):

| Model | Pooled R² (mean ± CI) | trajectories with pooled R² < 0 | Signal-averaged R² (mean, SD) | trajectories with signal-averaged R² < 0 |
|---|---|---|---|---|
| Koopman | 0.69 ± 0.03 (min 0.45) | 0/50 | 0.36 (0.76) | 6/50 (driven by P_vp, mean R² −2.16) |
| LSTM | −0.59 ± 0.11 | 47/50 | −21.1 (19.6) | 50/50 |
| GRU | −0.31 ± 0.07 | 45/50 | −5.09 (2.77) | 50/50 |
| BiLSTM | −0.30 ± 0.07 | 44/50 | −13.2 (16.2) | 50/50 |
| MLP | −17.6 ± 10.5 (median 0.12; 11/50 rollouts diverge) | 20/50 | −114 (284) | 38/50 |
| AR(20) | 0.33 ± 0.01 | 0/50 | −0.62 (0.51) | 50/50 |
| DLinear | 0.98 ± 0.00 | 0/50 | 0.96 (0.07) | 0/50 |
| NLinear | 0.98 ± 0.00 | 0/50 | 0.95 (0.07) | 0/50 |

Table 3 and the clean row of Table 5 use the pooled convention for every model and are identical by construction (same
predictions). The per-signal Koopman R² (mean over signals of the Table 4 values) is 0.36; the manuscript reports 0.69 (pooled)
as the headline value.

## 3. Frozen checkpoints and predictions behind every model row

All manuscript numbers come from committed weights or committed predictions; the reproduction scripts retrain nothing except the
analytic OLS fit of the AR(20) baseline.

| Model row | Rests on | Notes |
|---|---|---|
| Koopman | `results/koopman/csv_data_500_12sigs_2025_06_18_18_50_13_876051_model.ckpt` (17,239,600 parameters; hyper-parameters in `ckpt["params"]`) | rolled out on **test1** by `export_manuscript_tables.py` (float64 by default) → `results/tables/koopman_test1_postprocessing_results.pkl` (keys `true_per_trajectory`, `pred_per_trajectory`, `pct_per_traj_ps`, `r2_per_signal`, …, plus `split`, `checkpoint`, `rollout_dtype`, `device`). The older `results/koopman/koopman_postprocessing_results.pkl` is a **val1** evaluation (17.09 %RMSE with its own averaging; val 17.30 / test 17.54 with the shared metric functions); it is retained but not used by any table. |
| LSTM, GRU, BiLSTM | `results/{lstm,gru,bilstm}/*_model.ckpt` and `results/{lstm,gru,bilstm}/*_postprocessing_results.pkl` (test1) | predictions read from the committed pickles; bit-identical on every platform |
| DLinear, NLinear | `checkpoints/{dlinear,nlinear}_baseline.pt`, `results/{dlinear,nlinear}/*_postprocessing_results.pkl` (test1) | trained by `scripts/experiments/task_a_dlinear_nlinear.py` (about two minutes); predictions read from the committed pickles |
| MLP | `checkpoints/mlp_baseline.pt` (269,324 parameters) and the **frozen test1 predictions** `results/mlp/mlp_postprocessing_results.pkl` | see below |
| AR(20) | analytic OLS fit on train1 (`build_tables_figures.ar_pred`; 240 coefficients, no file) | refitted on every run; deterministic |

The script asserts that every baseline pickle's `true_per_trajectory` equals the test1 ground truth.

**Why the MLP predictions are frozen.** The autoregressive MLP baseline (clip ± 20 in normalised units) diverges (%RMSE > 100 %),
and its 1499-step **float32** rollout therefore amplifies CPU-architecture floating-point differences beyond manuscript rounding
(committed platform, macOS arm64: %RMSE 132.2 ± 55.1, pooled R² −17.63 ± 10.45; x86-64 container: 132.8 ± 55.2, −17.73 ± 10.46;
129 of 1459 metrics differed, 95 beyond off-by-one rounding, all belonging to the MLP row). The MLP predictions of the committed
run are therefore frozen in `results/mlp/mlp_postprocessing_results.pkl` (same keys and convention as the other baseline pickles,
bit-identical to the predictions behind `results/tables/`) and loaded by `export_manuscript_tables.py` by default, so the MLP rows
of Tables 3/4/5 reproduce exactly on every platform. On every run the checkpoint is nevertheless re-rolled in float32 and float64
and compared with the frozen predictions (`results/tables/mlp_recompute_check.json`): the float32 re-roll is **gated at 2 %
relative** on mean %RMSE and pooled R² (observed on x86-64: +0.39 % and −0.57 %); the float64 re-roll is informational. The
**float64** MLP rollout is platform-independent (133.6309060 %RMSE on arm64 vs. 133.6309062 on x86-64; pooled R² −17.6786 on both)
but differs from the manuscript's float32 rollout by +1.0 pp %RMSE. `--recompute-mlp` re-rolls the checkpoint instead of loading the
frozen predictions.

**Other conventions.** The MLP and AR(20) rows of Table 4 are produced with the shared functions of
`scripts/experiments/build_tables_figures.py` (`mlp_pred`, `ar_pred`); the Table 5 clean row is identical to Table 3 by construction
(same predictions), while the noise harnesses' own clean baselines (`clean_baseline` keys of `results/noise_robustness_baselines.json`)
differ marginally for the RNNs (LSTM 96.8 vs 97.8; BiLSTM 77.2 vs 76.4; GRU R² −0.34 vs −0.31) because of warm-up handling; the
noisy rows are taken from the JSONs unchanged (Koopman: `results/noise_robustness.json`; RNN/MLP/AR: `results/noise_robustness_baselines.json`;
DLinear/NLinear: `results/experiments/noise_robustness_linear.json`).

## 4. Statistics (`results/tables/statistics.json`)

The statistical unit is the test trajectory (n = 50); all 95 % CIs are 1.96·SD/√50 across trajectories (also the per-signal CIs of
Table 4, computed from the 50 per-trajectory per-signal values); hypothesis tests are paired across trajectories. Computed on the
per-trajectory %RMSE (`pct_per_traj_ps`) of the Table 3 predictions:

* **Shapiro–Wilk:** p < 0.05 for all six dynamical models (Koopman W = 0.82, p = 3.2×10⁻⁶; LSTM p = 0.038; GRU p = 0.014;
  BiLSTM p = 1.2×10⁻³; MLP p = 3.0×10⁻¹⁰; AR(20) p = 2.4×10⁻³) → non-parametric tests.
* **Friedman** across the six dynamical models (Koopman, LSTM, GRU, BiLSTM, MLP, AR(20); k = 6, n = 50):
  χ² = 175.55, df = 5, p = 4.8×10⁻³⁶.
* **Paired two-sided exact Wilcoxon signed-rank**, Koopman vs. each baseline, Bonferroni × 5: GRU, LSTM, BiLSTM, AR(20): W = 0,
  50/50 trajectories worse than Koopman, p = 1.78×10⁻¹⁵ (adjusted 8.9×10⁻¹⁵); MLP: W = 20, 47/50 worse, p = 6.6×10⁻¹³
  (adjusted 3.3×10⁻¹²).
* DLinear/NLinear are direct (non-autoregressive) forecasters and are not part of the omnibus test.

`results/stats_exact.json` (`scripts/experiments/task1_stats_exact.py`) is an earlier four-model version of the same analysis
(Friedman χ² = 107.57); `statistics.json` is the six-model analysis reported in the manuscript.

## 5. Numerical reproducibility across platforms

The 1499-step autoregressive rollout amplifies floating-point differences. For the frozen Koopman checkpoint on test1:

| Platform | Koopman mean %RMSE | 95 % CI | pooled R² |
|---|---|---|---|
| training machine, GPU (RTX 3070 Ti), float32 — `results/experiments/table3_overall_comparison.csv` | 17.5 (17.54) | 1.44 | 0.691 (global pooled) |
| training machine, GPU, float32 — `results/noise_robustness.json` clean baseline | 17.54 | 1.49 | 0.686 (mean per-trajectory pooled) |
| CPU, float32 | 17.46 | — | 0.69 |
| CPU, float64 — committed `results/tables/*` | 17.50 | 1.47 | 0.688 (mean per-trajectory pooled); 0.692 (global pooled) |

All values round to **17.5 %**; per-signal Koopman values agree to ≤ 0.1 pp; W = 0 for all four Wilcoxon comparisons on every
platform; the RNN/DLinear/NLinear predictions are read from the committed pickles and are bit-identical everywhere; the MLP
predictions are frozen (section 3). `results/tables/run_info.json` records the platform of the committed run (CPU, float64,
torch 2.12.1, macOS 15.6 / Apple Silicon, Python 3.11.15). The manuscript reports the Koopman row as 17.5 ± 1.5 %RMSE and pooled
R² 0.69 ± 0.03, and all manuscript tables equal `results/tables/` exactly at printed precision.

## 6. Container verification (Docker image + GitHub Actions)

**What runs.** `Dockerfile` (python:3.11-slim, CPU wheel of torch 2.6.0, every pin of `environment/requirements-pinned.txt`,
non-editable install of the package, the frozen checkpoints and the committed results) with `scripts/reproduce.sh` as default
command. The workflow `.github/workflows/reproduce.yml` (push to `main`, pull requests, `v*` tags, manual) builds the image, runs the
container with the repository mounted **read-only** (only `out/` writable), and:

1. downloads `csv_data_500_12sigs_test1_{x,u}.csv` and `csv_data_500_12sigs_train1_x.csv` from the Zenodo dataset record
   10.5281/zenodo.21163127 (record 21163128), because `data/*.csv` are Git-LFS pointers in a plain checkout, and verifies their MD5
   against the record (`normalization_{mean,std}.npy` are plain files in the repository and are MD5-verified as well; the Zenodo
   files are byte-identical to the LFS objects — SHA-256 of the downloads equals the LFS `oid`);
2. runs `scripts/tables/export_manuscript_tables.py --out-dir /workspace/out` (float64 Koopman rollout on CPU; all 50 test
   trajectories, 1499 steps) — Koopman rollout ≈ 42 s, MLP re-roll check ≈ 15 s, AR(20) OLS + rollout ≈ 10 s on the 4-vCPU runner;
3. runs `scripts/tables/compare_results.py --committed results/tables --fresh /workspace/out`, uploads `out/` as the workflow
   artifact `reproduction-tables`, and on `main` / `v*` pushes the verified image to `ghcr.io/cellularsyntax/cardiokoop`
   (tags `sha-<short>`, `latest`, `v*`; digest in `out/image_digest.txt` and in the job summary).

**Pass criteria** (`compare_results.py`, 1467 metrics): every number is compared *as printed in the manuscript* — Table 3 %RMSE and
CI to 1 decimal, pooled R² and CI to 2 decimals, parameter counts / inference times / speed-ups exact; Table 4 RMSE, %RMSE, CIs,
bias and LoA to 1 decimal, R² and CI to 2 decimals (8 models × 12 signals × 9 values); Table 5 %RMSE to 1 decimal, R² to 2
decimals (clean row recomputed, noisy rows read from the committed JSONs); statistics: Friedman χ² to 2 decimals, Shapiro W to
3 decimals, every p-value within a factor of 2, Wilcoxon W to the integer, trajectory counts (worse/better/ties, negative-R²
counts) exact, summary statistics to 1 decimal; `r2_conventions.json` means/SDs/CIs/medians/min/max to 2 decimals, global pooled
R² to 3 decimals; the MLP float32 re-roll within 2 % relative of the frozen predictions. A change of exactly one unit in the last
printed digit is tolerated (unless `REPRO_STRICT=1`) but is listed in `out/compare_report.md`; anything larger fails the job.

**What a green run proves.** The frozen checkpoints, the committed baseline predictions, the Zenodo splits and the code in the
repository regenerate every number of the manuscript's Tables 3–5 and statistics paragraph, at the precision at which they are
printed, in a pinned environment on an independent x86-64 machine. The verification runs of the v1.2.0 code report
1467 metrics, 1463 identical at printed precision, 0 off-by-one, 0 violations, 4 informational (float64 re-roll and bit-identity
flags); container wall time ≈ 100 s (data download ≈ 90 s, export ≈ 80 s), total job ≈ 7 min including the image build.

**Release image.** `ghcr.io/cellularsyntax/cardiokoop:v1.2.0`, built and pushed by the tag-triggered run of `reproduce.yml`.
The `:v1.2.0` image digest is recorded in the v1.2.0 GitHub release notes
(`https://github.com/CellularSyntax/CARDIOKOOP/releases/tag/v1.2.0`) and in the Zenodo record description
(10.5281/zenodo.22776287); verify with `docker buildx imagetools inspect ghcr.io/cellularsyntax/cardiokoop:v1.2.0`.

## 7. How to run

**Docker (one command; ≈ 5 min build, a few minutes run on a laptop CPU):**

```bash
docker pull ghcr.io/cellularsyntax/cardiokoop:v1.2.0
docker run --rm -v "$PWD/out:/workspace/out" ghcr.io/cellularsyntax/cardiokoop:v1.2.0
# or build locally: docker build -t cardiokoop . && docker run --rm -v "$PWD/out:/workspace/out" cardiokoop
```

`out/` then contains the regenerated `table3_overall.*`, `table4_per_signal_full.*`, `table5_noise.*`, `statistics.json`,
`r2_conventions.json`, `koopman_test1_postprocessing_results.pkl`, `mlp_recompute_check.json`, `run_info.json` and
`compare_report.md`. Options: `-e REPRO_THREADS=4`, `-e REPRO_DTYPE=float32`, `-e REPRO_STRICT=1`,
`-e CARDIOKOOP_DATA_DIR=/data -v <local splits>:/data`.

**Local pinned environment:**

```bash
git clone https://github.com/CellularSyntax/CARDIOKOOP.git && cd CARDIOKOOP
git lfs pull                                   # not needed for the Zenodo archive (data files already resolved)
python -m venv .venv && source .venv/bin/activate
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu   # or the CUDA wheel
pip install -r environment/requirements-pinned.txt && pip install -e .
python scripts/tables/export_manuscript_tables.py                          # writes results/tables/ (~1 min on CPU)
python scripts/tables/compare_results.py --committed results/tables --fresh <dir>   # compare a run written elsewhere
python scripts/experiments/run_all.py                                       # experiments, Figure 5, Figs. S4, S6-S10
```
