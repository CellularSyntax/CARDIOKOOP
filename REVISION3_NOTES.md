# CARDIOKOOP — Revision 3 notes (journal *Array*, minor revision; release v1.1.0)

Purpose of this document: give every number, table and figure in the manuscript
"Real-Time Hemodynamic Prediction via Control-Aware Koopman Operator Models" a committed
file of origin and the script that regenerates it, and document the conventions and
corrections introduced in revision 3.

Evaluation split for every reported number: the seed-42 **test1** split
(`data/csv_data_500_12sigs_test1_{x,u}.csv`; 50 trajectories × 1500 steps × 12 signals,
1499-step autoregressive horizon). Frozen Koopman checkpoint:
`results/koopman/csv_data_500_12sigs_2025_06_18_18_50_13_876051_model.ckpt` (17,239,600 parameters).
Statistical unit: the test trajectory (n = 50); 95 % CI = 1.96·SD/√50 across trajectories.

## 2. R² conventions (definitions in `results/revision3/r2_conventions.json`)

Three R² definitions occur in the manuscript; revision 3 states explicitly which is used where.

| Convention | Definition | Used in |
|---|---|---|
| **Pooled per-trajectory R²** | 1 − SS_res/SS_tot over all 12 signals × 1500 steps of one trajectory concatenated (`_common.r2_flat`); reported as mean ± 95 % CI over the 50 trajectories | Table 3, Table 5, Fig. 5g, Fig. S10 caption, Table S4 |
| **Per-signal R²** | `sklearn.metrics.r2_score` of one signal of one trajectory; mean ± 95 % CI over trajectories | Table 4, Fig. 5h |
| **Signal-averaged per-trajectory R²** | mean of the 12 per-signal R² of one trajectory (`r2_per_trajectory` key of the pickles) | "trajectories with R² < 0" statements of the per-signal analysis |

Test1 results (`r2_conventions.json`):

| Model | Pooled R² (mean ± CI) | trajectories with pooled R² < 0 | Signal-averaged R² (mean, SD) | trajectories with signal-averaged R² < 0 |
|---|---|---|---|---|
| Koopman | 0.69 ± 0.03 (min 0.45) | 0/50 | 0.36 (0.76) | 6/50 (driven by P_vp, mean R² −2.16) |
| LSTM | −0.59 ± 0.11 | 47/50 | −21.1 (19.6) | 50/50 |
| GRU | −0.31 ± 0.07 | 45/50 | −5.09 (2.77) | 50/50 |
| BiLSTM | −0.30 ± 0.07 | 44/50 | −13.2 (16.2) | 50/50 |
| MLP | −17.6 ± 10.5 (median 0.12; 11/50 rollouts diverge) | 20/50 | −114 (284) | 38/50 |
| AR(20) | 0.33 ± 0.01 | 0/50 | −0.62 (0.51) | 50/50 |
| DLinear | 0.98 ± 0.00 | 0/50 | 0.96 (0.07) | 0/50 |
| NLinear | 0.98 ± 0.00 | 0/50 | 0.95 (0.07) | 0/50 |

The revision-1 Table 3 R² row (Koopman 0.74, LSTM −6.5, GRU −1.46, BiLSTM −2.68, AR(20) 0.06, MLP −38.53) mixed
conventions and splits and is not reproducible from any committed file; it is replaced by the pooled row above, so that
Table 3 and the clean row of Table 5 are identical by construction. The per-signal Koopman R² (mean over signals of the
Table 4 values) is 0.36; the manuscript now reports 0.69 (pooled) as the headline value.

## 3. Validation-vs-test pickle issue and its resolution

* `results/koopman/koopman_postprocessing_results.pkl` (revision 1, source of the original Table 4 Koopman row) was
  generated on the **val1** split (mean %RMSE 17.09 with the pickle's own averaging; val 17.30 / test 17.54 with the
  revision-2 metric functions). Every baseline pickle (`results/{lstm,gru,bilstm,dlinear,nlinear}/`) is test1.
* Resolution: `scripts/revision3/export_manuscript_tables.py` rolls the frozen checkpoint out on **test1** and writes
  `results/revision3/koopman_test1_postprocessing_results.pkl` with the same keys as the baseline pickles
  (`true_per_trajectory`, `pred_per_trajectory`, `pct_per_traj_ps`, `r2_per_signal`, …, plus `split`, `checkpoint`,
  `rollout_dtype`, `device`). Table 4 (Koopman row) and all Koopman statistics are computed from this test1 evaluation.
  The revision-1 val1 pickle is kept unchanged for provenance and is not used by any revision-2/3 table.
* MLP and AR(20) rows of the revision-1 Table 4 were produced by older code paths (different clipping / fitting details);
  they are regenerated with the revision-2 functions (`build_tables_figures.mlp_pred`: committed
  `checkpoints/mlp_baseline.pt`, autoregressive rollout with clip ±20 in normalised units; `build_tables_figures.ar_pred`:
  OLS AR(20) per signal fitted on train1). Largest changes: MLP P_vp %RMSE 424 → 356, AR(20) P_vp 68 → 39.
* LSTM, GRU, BiLSTM, DLinear, NLinear rows are read from the committed pickles and are unchanged (≤ 0.1 rounding).
* The script asserts that every baseline pickle's `true_per_trajectory` equals the test1 ground truth.

## 4. Statistics recomputation (`results/revision3/statistics.json`)

Revision-1 `results/stats_exact.json` covered four models (Koopman, LSTM, GRU, BiLSTM; Friedman χ² = 107.57), while the
Methods describe an omnibus test over the six dynamical models with five Bonferroni-corrected comparisons; the reported
"Bonferroni-adjusted p = 8.88 × 10⁻¹⁶" was the unadjusted one-sided floor. Recomputed on the per-trajectory %RMSE
(`pct_per_traj_ps`, n = 50) of the Table 3 predictions:

* Shapiro–Wilk: p < 0.05 for all six dynamical models (Koopman W = 0.82, p = 3.2×10⁻⁶; LSTM p = 0.038; GRU p = 0.014;
  BiLSTM p = 1.2×10⁻³; MLP p = 3.0×10⁻¹⁰; AR(20) p = 2.4×10⁻³) → non-parametric tests.
* Friedman (Koopman, LSTM, GRU, BiLSTM, MLP, AR(20); k = 6, n = 50): **χ² = 175.55, df = 5, p = 4.8 × 10⁻³⁶**.
* Paired two-sided exact Wilcoxon signed-rank, Koopman vs. baseline, Bonferroni × 5:
  GRU, LSTM, BiLSTM, AR(20): W = 0, 50/50 trajectories worse than Koopman, **p = 1.78 × 10⁻¹⁵ (adjusted 8.9 × 10⁻¹⁵)**;
  MLP: W = 20, 47/50 worse, **p = 6.6 × 10⁻¹³ (adjusted 3.3 × 10⁻¹²)**.
* DLinear/NLinear are direct (non-autoregressive) forecasters and are not part of the omnibus test.

Suggested Methods sentence: "The statistical unit throughout is the test trajectory (n = 50). All 95 % CIs are
1.96·SD/√50 across trajectories (also the per-signal CIs of Table 4, computed from the 50 per-trajectory per-signal
values); hypothesis tests are paired across trajectories."

## 6. CPU-vs-GPU platform note

The 1499-step autoregressive rollout amplifies floating-point differences. For the frozen checkpoint on test1:

| Platform | Koopman mean %RMSE | 95 % CI | pooled R² |
|---|---|---|---|
| authors' workstation, GPU (RTX 3070 Ti), float32 — `results/revision2/table3_overall_comparison.csv` (revision 2) | 17.5 (17.54) | 1.44 | 0.691 (global pooled) |
| authors' workstation, GPU, float32 — `results/noise_robustness.json` clean baseline (revision 1) | 17.54 | 1.49 | 0.686 (mean per-trajectory pooled) |
| CPU, float32 | 17.46 | — | 0.69 |
| CPU, float64 — committed `results/revision3/*` | 17.50 | 1.47 | 0.688 (mean per-trajectory pooled); 0.692 (global pooled) |

All values round to 17.5 %; per-signal Koopman values agree to ≤ 0.1 pp; W = 0 for all four Wilcoxon comparisons on
every platform; the RNN/DLinear/NLinear predictions are read from the committed pickles and are bit-identical everywhere.
`results/revision3/run_info.json` records the platform of the committed run (CPU, float64, torch 2.12.1). The authors
can regenerate `results/revision3/` on the original workstation with the same command; the manuscript quotes the
authors' GPU CI "17.5 ± 1.4" (revision-2 run), the CPU-f64 run gives 17.5 ± 1.5.
